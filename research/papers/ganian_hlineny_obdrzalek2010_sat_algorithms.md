**Paper:** "Better algorithms for satisfiability problems for formulas of bounded rank-width"
**Authors:** Robert Ganian, Petr Hliněný, Jan Obdržálek
**arXiv:** 1006.5621 (June 2010)

## 1. Overview

This paper provides **single-exponential FPT algorithms** for #SAT and MAX-SAT parameterized by rank-width, achieving an **exponential speedup** over previous clique-width-based approaches.

**Main Result (Theorem 1.1):**
$$O(t^3 \cdot 2^{3t(t+1)/2} \cdot |\phi|)$$
where $t$ is the rank-width of the formula $\phi$.

## 2. Background: Why Rank-Width?

### 2.1 The Problem with Clique-Width

Previous best algorithm (Fischer-Makowsky-Ravve 2007):
- Single-exponential in **clique-width**
- But clique-width can be **exponentially larger** than rank-width!

**Proposition 2.10:**
- $\text{rwd}(\phi) \leq 2 \cdot \text{cwd}(\phi)$
- There exist $\phi$ with $\text{cwd}(\phi) \geq 2^{\text{rwd}(\phi)/4 - 1}$

**Implication:** Algorithms exponential in clique-width become **doubly-exponential** in rank-width!

### 2.2 Rank-Width Relationships

**Theorem 2.2:**
- $\text{rwd}(G) \leq \text{cwd}(G) \leq 2^{\text{rwd}(G)+1} - 1$
- $\text{rwd}(G) \leq \text{bw}(G) \leq \text{tw}(G) + 1$
- Tree-width cannot bound rank-width (cliques have rw=1)
- $\text{rwd}(G) = 1$ iff $G$ is **distance-hereditary**

### 2.3 Tractability of Rank-Width

**Theorem 2.3 (Hliněný-Oum 2008):** There is an FPT algorithm to either:
- Find rank-decomposition of width $\leq t$, or
- Confirm rank-width $> t$

This is **not known** for clique-width (for $k > 3$)!

## 3. Technical Framework

### 3.1 Signed Graphs for CNF Formulas

**Definition 2.7 (Formula Graph $F_\phi$):**
- $V(F_\phi) = W \cup C$ (variables $W$, clauses $C$)
- $wc \in E^+(F_\phi)$ iff literal '$w$' occurs in clause $c$
- $wc \in E^-(F_\phi)$ iff literal '$\neg w$' occurs in clause $c$

**Example:**
```
φ = (x ∨ y) ∧ (¬x ∨ z)

Variables W = {x, y, z}
Clauses C = {c₁, c₂}

E⁺: {(x,c₁), (y,c₁), (z,c₂)}
E⁻: {(x,c₂)}
```

### 3.2 Signed Rank-Width

**Definition 2.8:**
$$\text{rwd}(\phi) = \text{branch-width of } \rho^\pm_{F_\phi}$$

where the **signed cut-rank function**:
$$\rho^\pm_G(U) = \rho_{G^+}(U) + \rho_{G^-}(U)$$

### 3.3 Labeling Parse Trees

**Definition 2.5:** A $t$-labeling parse tree is a rooted subcubic tree where:
- Leaves contain $\odot$ (create single vertex with label $\{1\}$)
- Internal nodes contain composition operators $\otimes[g | f_1, f_2]$

**Key Operations:**
- **$t$-labeling join** $\bar{G}_1 \otimes \bar{G}_2$: Add edges where $|lab_1(u) \cap lab_2(v)|$ is odd
- **$t$-relabeling** $f$: Linear transformation $f: GF(2)^t \to GF(2)^t$

**Theorem 2.6:** $\text{rwd}(G) \leq t$ iff $G$ can be generated by a $t$-labeling parse tree.

### 3.4 Extended to Signed Graphs

**Definition 2.9:** A $(t^+, t^-)$-labeling parse tree $T = (T^+, T^-)$ is a pair with:
- $T^+$ is $t^+$-labeling parse tree generating $G^+$
- $T^-$ is $t^-$-labeling parse tree generating $G^-$
- Same underlying tree structure

## 4. The #SAT Algorithm

### 4.1 Main Theorem

**Theorem 3.1:** Given CNF formula $\phi$ and $(t^+, t^-)$-labeling parse tree:
$$\text{Time: } O(t^3 \cdot 2^{3t(t+1)/2} \cdot |\phi|)$$
where $t = \max(t^+, t^-)$.

### 4.2 Key Concept: Assignment Shape

**Definition 3.4:** Assignment $\nu_1$ has shape $(\Sigma^+, \Sigma^-, \Pi^+, \Pi^-)$ in $\tilde{F}_1$ if:

**I. Recorded Information:**
- $\Sigma^+$ = subspace spanned by $lab^+(\nu_1^{-1}(1))$ (true variables)
- $\Sigma^-$ = subspace spanned by $lab^-(\nu_1^{-1}(0))$ (false variables)

**II. Expectation Constraint:** For every clause $c$:
- Either $c$ is satisfied by current assignment, OR
- $lab^+(c)$ not orthogonal to $\Pi^+$ or $lab^-(c)$ not orthogonal to $\Pi^-$

The $(\Pi^+, \Pi^-)$ encodes **what we expect** from the rest of the formula!

### 4.3 Orthogonality and Adjacency

**Lemma 3.2:** In $\bar{G} \otimes \bar{H}$, vertex $y \in V(\bar{H})$ is adjacent to some $x \in X \subseteq V(\bar{G})$ iff the subspace spanned by labelings of $X$ is **not orthogonal** to labeling of $y$.

This is the key insight enabling the exponential speedup!

### 4.4 Algorithm Structure (Algorithm 3.6)

```
Input: CNF φ, (t⁺,t⁻)-labeling parse tree Tφ

1. Initialize all Table_z entries to 0

2. Process nodes leaves-to-root:
   a) Clause leaf c:
      Table_c[∅,∅,Π⁺,Π⁻] ← 1 if not orthogonal to {1}

   b) Variable leaf ℓ:
      Table_ℓ[⟨{1}⟩,∅,Π⁺,Π⁻] ← 1  (true assignment)
      Table_ℓ[∅,⟨{1}⟩,Π⁺,Π⁻] ← 1  (false assignment)

   c) Internal node z with children x, y:
      For all 12-tuples of subspaces satisfying conditions:
        Table_z[Σ⁺_z,Σ⁻_z,Π⁺_z,Π⁻_z] +=
          Table_x[...] × Table_y[...]

3. Return Σ Table_r[Σ⁺,Σ⁻,∅,∅] at root r
```

### 4.5 State Space Analysis

**Lemma 3.3:** Number of subspaces of $GF(2)^t$ satisfies:
$$S(t) \leq 2^{t(t+1)/4} \text{ for } t \geq 12$$

**Table Size:** $O(S(t)^4)$ per node

**Per-Node Computation:** Loop over 6 independent subspaces, compute remaining 6:
$$O(t^3 \cdot S(t)^6) = O(t^3 \cdot 2^{6t(t+1)/4}) = O(t^3 \cdot 2^{3t(t+1)/2})$$

### 4.6 Why This Works: The "Expectation" Trick

**Key Insight (from Bui-Xuan-Telle-Vatshelle 2010):**
- Standard DP records only what's been computed
- **Expectation-based DP** also records what we need from the future
- This dramatically reduces state space in rank-width algorithms

Without expectation: Would need all possible ways clauses could be satisfied
With expectation: Only need $S(t)^2$ possibilities for $(\Pi^+, \Pi^-)$

## 5. The MAX-SAT Algorithm

### 5.1 Defective Shape

**Definition 4.2:** Assignment $\nu_1$ has **defective shape** $(\Sigma^+, \Sigma^-, \Pi^+, \Pi^-)$ if there exists $C_0 \subseteq C \cap V(F_1)$ such that $\nu_1$ is of shape $(\Sigma^+, \Sigma^-, \Pi^+, \Pi^-)$ in $\tilde{F}_1 - C_0$.

The **defect** = minimum $|C_0|$ (unsatisfied clauses not expected to be satisfied).

### 5.2 Algorithm Modification

**Algorithm 4.3:** Same structure but:
- Table entries store **minimum defect** instead of count
- Use min instead of sum in aggregation
- Initialize with $\infty$ instead of 0

**Theorem 4.1:** Same time complexity $O(t^3 \cdot 2^{3t(t+1)/2} \cdot |\phi|)$

## 6. Complexity Analysis

### 6.1 Runtime Comparison

| Algorithm | Complexity | Parameter |
|-----------|------------|-----------|
| Fischer-Makowsky-Ravve 2007 | $O(f(k) \cdot n)$ | $k$ = clique-width |
| **This paper** | $O(t^3 \cdot 2^{3t(t+1)/2} \cdot n)$ | $t$ = rank-width |

For typical cases where $k = 2^{t/2}$:
- Old: $2^{2^{t/2}} \cdot n$ (doubly-exponential in $t$)
- New: $2^{3t^2/2} \cdot n$ (singly-exponential in $t$)

### 6.2 Space Complexity

- Table size per node: $O(S(t)^4) = O(2^{t(t+1)})$
- Total nodes: $O(|V(F_\phi)|) = O(|\phi|)$
- Total space: $O(2^{t(t+1)} \cdot |\phi|)$

### 6.3 Hidden Constants

> "Note that there are no 'large constants' hidden in the O-notation."

This is crucial for practical applicability!

## 7. Why Rank-Width is Appropriate for SAT

### 7.1 Distance-Hereditary Base Case

**Theorem 2.2(e):** $\text{rwd}(G) = 1$ iff $G$ is distance-hereditary.

Distance-hereditary graphs form a rich class including:
- Trees, cycles
- Cographs
- Ptolemaic graphs

### 7.2 Sparse vs Dense Trade-off

For **sparse** formula graphs:
- Bounded rank-width ↔ bounded tree-width
- Either parameter works

For **dense** formula graphs (large bipartite cliques):
- Tree-width is unbounded
- But satisfiability may be easier (simpler structure)
- Rank-width captures this structure

## 8. Technical Details

### 8.1 GF(2) Linear Algebra

All operations use binary field $GF(2)$:
- Addition = XOR
- Multiplication = AND
- Efficient computation

### 8.2 Subspace Enumeration

**Lemma 6.3 (Ganian-Hliněný 2010):** Efficient indexing scheme for subspaces of $GF(2)^t$:
- Query time: $O(t^3)$
- Construction time: $O(2^{3t(t+1)/4} \cdot t^3)$

### 8.3 Parse Tree Construction

**Theorem 2.11:** FPT algorithm to compute $(t^+, t^-)$-labeling parse tree or confirm signed rank-width $> t$.

Based on partitioned rank-decomposition of auxiliary graph $G' = G^+ \cup G^-_0$.

## 9. Practical Implications

### 9.1 When to Use This Algorithm

**Good cases:**
- Formula graphs with low rank-width
- Dense but structured formulas
- When clique-width algorithms are too slow

**Not ideal:**
- Very sparse formulas (tree-width better)
- Rank-width close to $n/2$

### 9.2 Implementation Considerations

1. **Preprocessing:** Compute rank-decomposition (FPT)
2. **Table representation:** Use subspace indices
3. **Parallelization:** Nodes at same depth are independent
4. **Memory optimization:** Only need parent/children tables

### 9.3 Practical Values

For $t = 5$:
- $2^{3 \cdot 5 \cdot 6/2} = 2^{45} \approx 10^{13}$ operations per variable
- Still exponential but potentially feasible

For $t = 3$:
- $2^{3 \cdot 3 \cdot 4/2} = 2^{18} \approx 260,000$ operations
- Very practical!
